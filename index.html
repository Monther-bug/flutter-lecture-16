The idea

What is Firebase?

The problemA real login needs a server: a computer on the internet that stores accounts and checks passwords. Building one takes another language, a database and security work.
FirebaseGoogle's backend-as-a-service: a ready-made server you use from your app. The "backend" is the server side of an app; "as a service" means Google runs it for you.
Why Flutter apps use itNo server code to write, official Flutter packages (called FlutterFire), works on Android, iOS and web, free to start.

Step 6 · lib/main.dart

Start Firebase in main()

lib/main.dart
import 'package:firebase_core/firebase_core.dart';
import 'package:flutter/material.dart';

import 'firebase_options.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);
  runApp(const MyApp());
}
1Future<void> main() asyncmain now waits for something, so it is async (Lecture 18)
2ensureInitialized()Gets Flutter ready before a plugin talks to Android or iOS
3await Firebase.initializeApp(...)Connects to our project and waits until it is done
4runApp comes lastThe app starts only when Firebase is ready
Mobile App Development · Lecture 20

Read it line by line. If your main() already has other lines from earlier lectures (for example EasyLocalization.ensureInitialized() or a Provider), keep them: just make sure the binding line comes first and runApp comes last.

Authentication

Firebase Authentication: the big idea

UserOne account in your Firebase project (email, name, photo…)
ProviderHow a user proves who they are: Email/Password, Google, Apple, Phone… You switch each one on in the console
uidThe user's unique ID, a long text like kZ3x9QpL…. It never changes, even if the email changes
Current userFirebaseAuth.instance.currentUser gives a User?: a User, or null when nobody is signed in
Firebase remembers the signed-in user on the phone, so they stay signed in after the app restarts

Console · Authentication

Enable Email/Password in the console

  1. In the console, open your project → Authentication (left menu, under Security) → Get started
  2. Tab Sign-in method → click Email/Password
  3. Turn on the first switch, Email/Password. Leave "Email link (passwordless sign-in)" off
  4. Save → the provider list shows Email/Password as Enabled
  5. Open the Users tab: empty for now. Next lecture, our app fills it
If a provider is not enabled, sign-in fails with the error code operation-not-allowed.
